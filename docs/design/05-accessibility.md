# 05. アクセシビリティ

個人用アプリでも a11y をやる理由は 3 つ。
(1) 自分の体調・環境（片手操作、屋外の直射日光、疲れ目）で効く。
(2) a11y を満たした UI は結果的に構造が整理される。
(3) 後から直すコストが高い。

基準は **WCAG 2.2 AA**、および **Apple HIG**（→ [09-apple-hig.md](./09-apple-hig.md)）。
数値が食い違う場合は**厳しい側**を採る。実装仕様の答え合わせには HeroUI / React Aria を使う。

---

## 1. コントラスト

| 対象 | 最低比 |
|---|---|
| 通常テキスト（< 18.66px bold / < 24px） | **4.5:1** |
| 大きいテキスト（≥ 18.66px bold または ≥ 24px） | 3:1 |
| アイコン・入力欄の枠・グラフの線などの非テキスト | 3:1 |

HIG が示す表（09-apple-hig.md §1.2）は「〜17pt: 4.5:1 / 18pt: 3:1 / Bold: 3:1」。
**このプロジェクトは Bold でも本文サイズなら 4.5:1 を要求する**（日本語は字画が多く潰れやすいため）。

- 実測値と使ってよい色は **02-design-system.md §1.2** の表を参照
- **落とし穴: 塗りボタンの白文字。**`bg-[#4CAF50] text-white` は約 2.8:1 で未達。塗りを `#2E7D32` にする
- 非アクティブ状態でも 3:1 は確保する。「薄いから非アクティブ」ではなく「色 + ウェイト」で区別する
- 確認方法: Chrome DevTools の Inspect → Accessibility → Contrast、または Lighthouse

---

## 2. タップ領域

- **既定 44×44px / 絶対最小 28×28px**（HIG iOS の値。WCAG 2.2 の Target Size AA は 24px だが、
  モバイル PWA では HIG に合わせる）
- 見た目が小さいアイコンボタンは、透明なパディングで領域だけ広げる
- **間隔はサイズと同じくらい重要**（HIG の明言）
  - 枠のある要素（ボタン、入力欄）… 周囲に約 **12px**
  - 枠のない要素（テキストリンク、アイコンのみ）… 見えている端から約 **24px**
- **複雑なジェスチャを常用動線に使わない。**マルチフィンガー / 独自ジェスチャを避ける
- **ジェスチャには必ず代替手段を用意する。**「スワイプで閉じる」を作るならタップで閉じるボタンも置く
- カード内の削除ボタンのような「危険な小ボタン」は、主要操作から離して配置する

---

## 3. キーボード操作

| キー | 期待動作 |
|---|---|
| `Tab` / `Shift+Tab` | 視覚順序と一致した移動。モーダル内ではトラップされる |
| `Enter` / `Space` | ボタンの実行 |
| `Esc` | モーダル / シート / ポップオーバーを閉じる |
| `矢印` | セグメントコントロール・タブ・リスト内の移動 |

- **`<div onClick>` を押せる要素にしない。**`<button>` / `<a>` を使う。
  どうしても div が必要なら `role="button"` `tabIndex={0}` `onKeyDown`（Enter/Space）をセットで書く
- `focus:outline-none` を単独で書かない。必ず `focus-visible:ring-*` とセット（03-components.md §0）
- フォーカスは「見えるところ」にある。スクロール外にフォーカスが飛ばないこと

---

## 4. スクリーンリーダー / セマンティクス

- `<html lang="ja">` は設定済み（維持する）
- 見出しは `h1 → h2 → h3` の順に飛ばさない。各ページに `h1` が 1 つ
- **アイコンのみのボタンに `aria-label`**（現在 21 箇所で使用中。残りにも展開する）
- 装飾目的の SVG は `aria-hidden="true"` + `focusable="false"`
- 画像の `alt`: 食事写真は料理名を入れる。装飾画像は `alt=""`
- モーダル: `role="dialog"` `aria-modal="true"` `aria-labelledby`（03-components.md §3）
- 動的に変わる領域: `aria-live="polite"`（保存完了、解析結果）/ `"assertive"`（エラー）
- 進捗: `role="progressbar"` + `aria-valuenow` / `aria-valuemin` / `aria-valuemax`
- タブ: `role="tablist"` / `role="tab"` / `aria-selected` / `aria-controls`
- ナビの現在地: `aria-current="page"`

---

## 5. 色に依存しない情報伝達

ui-ux-pro-max の指摘（「バッジの意味を色だけに依存させない」）を全面適用する。

| 箇所 | 対応 |
|---|---|
| 食事カテゴリ（朝/昼/夕/間食） | 色 + 文字ラベル（実装済み。維持） |
| PFC バー | 色 + `P` / `F` / `C` の文字 + 数値 |
| 目標達成 / 未達 | 色 + アイコン + 文字 |
| グラフの系列 | 色 + 凡例 + 3 系列以上なら線種・マーカー形状 |
| 入力エラー | 枠色 + 直下のエラーテキスト + `aria-invalid` |

---

## 6. テキストの耐性

- **文字サイズ 200% でもレイアウトが壊れないこと。**固定 px 高さのボタンに長いラベルを入れない
- 折り返し前提で作る。`whitespace-nowrap` は数値と単位だけに使う
- `truncate` する場合は全文にアクセスする手段（`title`、詳細画面、展開）を用意する
- 日本語は禁則処理が効く。英数字混在の見出しには `break-words` を付ける
- **最小フォントサイズ 11px / 本文の既定 16px**（HIG iOS: 最小 11pt・既定 17pt → 02-design-system.md §2.2）
- **細いウェイトを使わない。**HIG は Ultralight / Thin / Light を避けよと明示している
- **入力欄の文字を 16px 未満にしない**（iOS Safari がフォーカス時に自動ズームする）
- テキストサイズを変えたとき、**重要な情報から大きくする。**タブのラベルまで一緒に大きくしない

---

## 7. モーション

- `prefers-reduced-motion: reduce` に必ず対応（**04-motion.md §6。現在未対応**）
- 自動再生・自動でめくれるものは停止できること（Daily Recap のスワイプ演出）
- 点滅は 1 秒あたり 3 回未満（光過敏性発作の閾値）
- WebGL は CSS の一括抑制で止まらない。JS で分岐する → [08-3d.md](./08-3d.md) §5

---

## 8. レスポンシブ確認

**375 / 768 / 1024 / 1440px** の 4 幅で必ず確認する（ui-ux-pro-max のチェックリスト）。
加えて PWA 特有の 2 点:

- **セーフエリア** — ノッチ / ホームインジケータに UI が重ならない（`env(safe-area-inset-*)`）
- **横向き** — スマホ横向きで下部ナビとコンテンツが破綻しない

---

## 9. 確認手順（毎回やる 5 分版）

1. **キーボードだけで**主要動線（食事を 1 件記録して削除）を最後まで通す
2. `Tab` でフォーカスリングが常に見えているか
3. Chrome DevTools → Lighthouse → Accessibility を実行（目標 95 以上）
4. DevTools のデバイスツールバーで 375px 表示 → 文字サイズ 200%
5. OS の「視差効果を減らす」を ON にして、動きが止まるか
