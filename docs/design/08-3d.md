参照: [ThreeUI](https://threeui.com/browse) — Three.js コンポーネントとインタラクティブシェーダーのカタログ

## 1. ThreeUI とは / 何を取り込むか

**何者か**
Three.js / WebGL 製のインタラクティブ UI コンポーネントを、ライブプレビュー付きで閲覧できるカタログ。
`/browse` でグリッド表示・検索・テーマ切替ができ、各コンポーネントのページで
**バリアント選択・コントロール（パラメータ調整）・ソースコードタブ**が見られる。
オープンソースの Community 版は 50 の親コンポーネント / 111 ルート / 164 のブラウズ結果を含み、
ログイン不要。`npm install @designcodeio/threeui` でも入る。
アプリコードと Community コンポーネントは MIT（同梱フォントは SIL OFL 1.1、Three.js は元の MIT）。

**特徴的なのは 3 点**
1. **プロシージャル志向** — 3D のヒーローやアイコンをテクスチャ資産なしで生成する。アセット配信量が増えない
2. **variant + controls** — 同じコンポーネントに「テーマ / ライティング / モーション / レイアウト」の調整軸が定義されている
3. **コピペ所有型 + プロンプト同梱** — ソースをそのまま持ってきて自分で保守する。coss ui と同じ思想

**このプロジェクトへの取り込み方**

| ThreeUI の考え方 | FitMealTracker での適用 |
|---|---|
| プロシージャル生成でアセットを減らす | `AvatarViewer` の matcap は既に Canvas で生成していてテクスチャ資産ゼロ。**この方針を維持する** |
| variant / controls で軸を明示 | アバターの見た目は「クリップ（種目）」「装備の表示」で既に軸化されている。新しい 3D を足すときも軸を先に定義する |
| ソースを所有する | **`@designcodeio/threeui` は依存として入れない。**必要な表現の実装だけを読んで自前で書く |

> **依存として入れない理由**: PWA でオフライン前提のアプリなので、初回ダウンロード量が体験に直結する。
> Three.js 本体だけでも十分重く、コンポーネントライブラリを丸ごと足す余地はない。
> ThreeUI は「実装の読み物・パラメータの参考値」として使う。

## 2. 3D を使ってよい場所 / 使わない場所

3D は「機能」か「演出」かを必ず先に決める。

| | 場所 | 判断 |
|---|---|---|
| ✅ 機能 | 運動タブの種目デモアバター | フォームを見せるという明確な役割がある。**維持** |
| ✅ 演出 | Daily Recap の背景・達成演出 | 1 日 1 回以下。04-motion.md の「演出枠」に該当 |
| ✅ 演出 | オンボーディングのヒーロー | 1 回しか見ない |
| ❌ | 食事の記録動線（撮影 → 解析 → 保存） | **3 タップで終わるべき動線に WebGL を挟まない** |
| ❌ | フォーム・リスト・グラフの装飾 | 情報密度を下げ、フレームを食うだけ |
| ❌ | 常時表示されるナビ・ヘッダ | 常時ループはバッテリーを削る（04-motion.md §7） |

**原則: 1 画面に WebGL Canvas は 1 つまで。**

## 3. パフォーマンス予算

### 3.1 読み込み

- **必ず `dynamic(..., { ssr: false })` で遅延読み込みする。**
  `GymSessionCard.tsx` の実装が正（セッション開始時にのみロード）
- 3D が表示される可能性のある画面に入った時点で **prefetch はしない**。実際に必要になってから読む
- ローディング中は静止画かスケルトンを出す（`loading: () => null` は「何も出ない時間」を作るので、
  読み込みが 300ms を超えるならプレースホルダを入れる — 03-components.md §8）

### 3.2 アセット予算

| 対象 | 目標 |
|---|---|
| GLB 1 ファイル | **500KB 以下** |
| 1 画面で読む 3D 合計 | 1MB 以下 |
| テクスチャ | 原則なし（matcap / vertexColors / プロシージャル） |

- 圧縮は **Draco**（ジオメトリ）/ **meshopt**、テクスチャが必要なら **KTX2**
- **`public/models/` に使っていない GLB を置かない。**デプロイ物に含まれて配信対象になる
  （現状 14 ファイル中、実際に参照されているのは 2 つ — 07-audit-backlog.md 参照）

### 3.3 レンダリング設定

```tsx
<Canvas
  dpr={[1, 1.5]}                       // モバイルは 1.5 で十分。2 は塗り面積が 1.8 倍になる
  gl={{ antialias: true, alpha: true, powerPreference: 'low-power' }}
  frameloop={playing ? 'always' : 'demand'}   // 静止中は描画を止める
  shadows={false}                      // リアルタイムシャドウマップは使わない
>
```

- **影は `ContactShadows` のみ。**シャドウマップは有効にしない（既に `ContactShadows` を採用済み）
- **ライトを置かない。**`MeshMatcapMaterial` + `vertexColors` で見た目を作る（既存 `AvatarViewer` の方式が正）
- ポストプロセス（bloom / DOF / SSAO）は使わない。モバイルでフレーム予算を使い切る
- `frustumCulled = false` は必要な箇所だけに限定する（アニメーションでバウンディングボックスが
  ずれるモデルへの対処であって、既定にしない）

### 3.4 停止条件（必須）

**動かし続けない。**以下のいずれかで必ず止める。

| 条件 | 対応 |
|---|---|
| 画面外にスクロールした | `IntersectionObserver` で `frameloop='never'` |
| タブが非アクティブ | `document.visibilityState === 'hidden'` で停止 |
| ユーザーが操作していない | アイドルループは持たせるが、`frameloop='demand'` + 必要時 `invalidate()` |
| `prefers-reduced-motion: reduce` | **ループを止め、静止ポーズを表示**（§5） |

アンマウント時は GLTF / テクスチャ / ジオメトリを `dispose()` する。
`useGLTF` のキャッシュは残るので、画面を行き来してもリークしないことを DevTools の Memory で確認する。

## 4. アクセシビリティ

WebGL の中身はスクリーンリーダーから完全に不可視。**3D にしか無い情報を作らない。**

- **Canvas が装飾なら `aria-hidden="true"`**、意味を持つなら親要素に代替テキストを置く
- 種目デモアバターは、**種目名・回数・セット数を必ずテキストでも表示する**（現状 OK。維持する）
- `OrbitControls` はキーボードで操作できない。**回転・ズームを前提にした情報提示をしない**
  （必要な角度は初期カメラで見えていること）
- Canvas 自体をタブ順に入れない（`tabIndex={-1}`）。中に操作対象が無いのにフォーカスが止まると混乱する
- コントラスト: 3D の上にテキストを重ねるときは、背景の明るさが動くので
  **半透明の下地を敷いて 4.5:1 を保証する**（05-accessibility.md §1）

## 5. `prefers-reduced-motion`

3D は CSS の一括抑制ルール（04-motion.md §6）では止まらない。**JS で明示的に分岐する。**

```tsx
const reduced = typeof window !== 'undefined'
  && window.matchMedia('(prefers-reduced-motion: reduce)').matches;

// ループを再生せず、最初のフレームで固定する
useEffect(() => {
  const action = actions[clip];
  if (!action) return;
  if (reduced) {
    action.reset().play();
    action.paused = true;   // 1 フレーム目で静止
    return;
  }
  action.reset().fadeIn(0.3).play();
  return () => { action.fadeOut(0.3); };
}, [actions, clip, reduced]);
```

**機能を消すのではなく、動きだけを消す。**種目のフォームが伝わる静止ポーズを選ぶこと。

## 6. フォールバック

- **WebGL が使えない環境がある**（古い端末、GPU ブラックリスト、省電力モード）。
  `Canvas` を `ErrorBoundary` で包み、失敗時は静止画（`docs/design/screens/avatar-*.png` 相当）に落とす
- GLB の取得に失敗したら、3D 領域ごと非表示にして周囲のレイアウトが崩れないこと
- **オフライン時**: GLB を Service Worker のキャッシュ対象にするかを決める。
  キャッシュするなら容量予算（§3.2）を守り、しないなら静止画フォールバックを必ず用意する

## 7. ThreeUI カタログの見方（実務メモ）

- `/browse` でグリッドを眺め、各コンポーネントページの **source タブ**を読む。
  「どのマテリアルで」「ライトを何個使って」「毎フレーム何を更新しているか」を見る
- **controls（パラメータ）は数値の参考値として価値がある。**
  減衰、回転速度、カメラ距離などを一から決めなくてよくなる
- 拾ってきた表現は、実装前に §3 の予算表に当てて **落とせるものを落としてから**入れる
  （ライト → matcap、テクスチャ → vertexColors、ポストプロセス → 削除）
- 添付されているプロンプトをそのままエージェントに渡すと、この規約を無視した実装が出てくる。
  **必ず §3 / §4 / §5 の制約を追記してから使う。**
