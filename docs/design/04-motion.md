# 04. モーション規約

出典の考え方: [60fps](https://60fps.design/) — 「見た目のスタイル」ではなく **インタラクションの文脈**で
動きを分類する。同じ課題を各社がどう解いているかを比較し、型として取り込む。

FitMealTracker は **1 日に何度も開き、1 回の滞在が短い道具**。
動きは「気持ちよさ」より **「今どこにいて、何が起きたか」を伝えるため**にある。

---

## 1. モーションの 4 つの役割

新しいアニメーションを足すときは、必ずこの 4 つのどれかに当てはめて 1 行で説明できること。
当てはまらないものは実装しない。

| 役割 | 意味 | 例 |
|---|---|---|
| **方向づけ** | 要素がどこから来てどこへ行くかを示す | ボトムシートが下から出る、モーダルが押した場所から開く |
| **フィードバック** | 操作を受け付けたことを即座に返す | ボタンの押し込み、チップの選択 |
| **連続性** | 状態の変化を追跡可能にする | 進捗バーの伸長、数値のカウントアップ、リストへの追加 |
| **演出** | 達成感・満足感を作る | Daily Recap、目標達成、連続記録の更新 |

**演出は「1 日 1 回以下しか見ないもの」に限る。**毎回の記録動線に演出を入れない。

### HIG のモーション原則（09-apple-hig.md §3）

- **意味なく動かさない。**過剰なモーションは注意を逸らし、不快感を与える
- **モーションを唯一の伝達手段にしない。**必ずテキストなどの代替を併置する
- **頻繁に起きる操作にはモーションを足さない。**毎回目にする動きは、その都度ユーザーの時間を奪う
- **フィードバックのモーションは現実的に。**上から出したものは上へ返す。横から出したものを下へ消さない
- **簡潔・正確に。**短く精密なフィードバックのほうが、大きなアニメーションより伝わる
- **モーションをキャンセルできるようにする。**アニメーションの完了を待たせない

## 2. タイミングトークン

| トークン | 値 | 用途 |
|---|---|---|
| `--dur-instant` | 100ms | 色の変化、ホバー |
| `--dur-fast` | 150ms | 小要素の出現・消滅、チップの選択 |
| `--dur-base` | 200ms | **既定。**モーダルのフェード、タブ切替 |
| `--dur-slow` | 300ms | ボトムシートのスライド、ページ間の遷移 |
| `--dur-deliberate` | 500ms | 進捗バー、カウントアップなど「見せる」変化 |

- **500ms を超えるものは演出のみ。**操作の応答に 500ms 超はかけない
- 距離が長いほど時間は長く。小さなチップに 300ms は遅すぎる

## 3. イージングトークン

| トークン | 値 | 使う場面 |
|---|---|---|
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | **既定。**位置と大きさの変化全般 |
| `--ease-decelerate` | `cubic-bezier(0, 0, 0, 1)` | 画面に **入ってくる**もの（シートの出現、進捗の伸長） |
| `--ease-accelerate` | `cubic-bezier(0.3, 0, 1, 1)` | 画面から **出ていく**もの（シートを閉じる） |
| `--ease-overshoot` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | 達成バッジなど、演出のみ |

- **`linear` はスピナーと進捗の不定表示だけ。**それ以外に使わない
- Tailwind の `ease-in-out` は既定のままだと平板に見える。上記のカスタム値を `tailwind.config.ts` の
  `transitionTimingFunction` に登録して使う

## 4. パフォーマンス規約（60fps を守る）

1 フレームの予算は **16.7ms**。これを守るための強制ルール:

- **アニメーションしてよいプロパティは `transform` と `opacity` だけ。**
  `width` / `height` / `top` / `left` / `margin` / `padding` をトランジションさせない（レイアウトが再計算される）
- 高さを変えたいとき:
  - 出現・消滅 → `transform: scaleY()` か `opacity` + `translateY`
  - どうしても高さが必要 → `grid-template-rows: 0fr → 1fr`（レイアウトを走らせるが 1 要素なら許容）
- **`transition-all` を使わない。**現状 23 箇所ある。変化するプロパティを明示する
  （`transition-transform` / `transition-colors` / `transition-opacity`）
- `will-change` は **アニメーション直前に付けて終わったら外す**。常時付けっぱなしにしない
- 大きな `backdrop-filter` / `blur` はモバイルで重い。オーバーレイの背景は `bg-black/40` の単純な半透明でよい
- 画像・3D（Three.js のアバター）は **画面外では止める**（`IntersectionObserver` でループを停止）→ [08-3d.md](./08-3d.md)
- リストの `key` を安定させる。key が変わると React が要素を作り直してアニメーションが飛ぶ

## 5. パターン集（そのまま使う）

### 5.1 押し込みフィードバック

```
active:scale-[0.98] transition-transform duration-100
```

主要 CTA は `active:scale-95` まで。すべての押せる要素に付ける。

### 5.2 ボトムシート（`ui/Modal.tsx`）

| 要素 | 開く | 閉じる |
|---|---|---|
| オーバーレイ | `opacity 0 → 1` / 200ms / standard | `1 → 0` / 150ms |
| シート本体 | `translateY(100%) → 0` / 300ms / decelerate | `0 → 100%` / 200ms / accelerate |

- **閉じるほうを開くより速く。**待たされる感覚が消える
- デスクトップの中央モーダルは `opacity 0→1` + `scale(0.96)→1` / 200ms / standard

### 5.3 リストへの追加（記録が増えたとき）

- 新しいカードを `opacity 0 → 1` + `translateY(8px) → 0` / 200ms / decelerate
- **複数同時に出るときだけ stagger 30〜50ms。**5 件を超えたら stagger をやめる（待ち時間になる）
- 削除は `opacity 1 → 0` + `scale(0.98)` / 150ms

### 5.4 タブ切替

- コンテンツは **クロスフェードのみ**（200ms）。左右スライドはページ全体の再レイアウトを誘発する
- 下部タブのアイコンは色変化のみ（100ms）。跳ねさせない（1 日に何十回も見る）

### 5.5 進捗・数値

- 進捗バー: `transform: scaleX()` / 500ms / decelerate（`width` ではなく `scaleX`）
- カウントアップ: 500ms 以内、`tabular-nums` で桁揺れを防ぐ。**小数は動かさない**（読めない）
- 目標達成の瞬間だけ overshoot を 1 回

### 5.6 解析中（Gemini）

- 300ms までは何も出さない
- それ以降はスケルトン。スケルトンのシマーは `opacity` の往復（1.5s / ease-in-out）で、
  `background-position` を動かすグラデーションより軽い
- **完了時は結果を静かにフェードイン**（200ms）。派手に出さない。ユーザーは値の確認をしたい

### 5.7 Daily Recap（演出枠）

ここは 60fps の事例をそのまま参考にしてよい唯一の場所。
ただし **スキップできること**、**`prefers-reduced-motion` で静止版になること**が条件。

## 6. `prefers-reduced-motion`（必須・現在未対応）

前庭障害のあるユーザーには実際に体調不良を引き起こす。**例外なく対応する。**

```css
/* globals.css */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

- JS で駆動する動き（Three.js のアバター、Recap のスライド）は
  `window.matchMedia('(prefers-reduced-motion: reduce)').matches` を見て分岐する
- 「動きを消す」であって「機能を消す」ではない。**遷移は即座に完了させ、情報は必ず届ける**

### HIG が挙げる具体策

Reduce Motion が ON のとき、CSS の一括抑制に加えて次を行う:

- スプリングを締めて**バウンドを減らす**
- **ジェスチャに直接追従する**アニメーションにする（自走させない）
- **z 軸（奥行き）の変化をアニメーションしない**
- **x / y / z 軸の遷移をフェードに置き換える**
  → ボトムシートの `translateY` は、Reduce Motion 時は `opacity` のみにする
- **ぼかしに出入りするアニメーションを避ける**
  → `backdrop-filter` を 0 → 20px と変化させない。最初から確定値で出す

## 7. アンチパターン

| やらない | 理由 |
|---|---|
| 操作の応答に 500ms 超 | 遅く感じる。体感の上限は 300ms 前後 |
| 毎回の記録完了で紙吹雪・跳ね | 3 回目には邪魔になる |
| `transition-all` | 意図しないプロパティが乗ってカクつく |
| 常時ループするアニメーション | バッテリーと注意を消費する。PWA では致命的 |
| スクロール連動の重い視差 | モバイルで最もフレーム落ちしやすい |
| 300ms 未満のためにスピナーを出す | 点滅にしか見えない |
| 同じ画面で 3 つ以上が同時に動く | どこを見ればいいか分からなくなる |
