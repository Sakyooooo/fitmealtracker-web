# 01. 参考リソースの要約と使い分け

> 調査日: 2026-08。各サイトは更新されるので、規約として運用するのはこのリポジトリ内のドキュメント側とし、
> 元サイトは「引き出しを増やす場所」として使う。

## 早見表

| リソース | 種類 | 何が得られるか | FitMealTracker での使いどころ |
|---|---|---|---|
| Inspora | インスピレーション | 最新のビジュアル / ブランド / モーション事例 | 新セクションのトーン決め、Daily Recap のようなビジュアル強めの画面 |
| 60fps | モーション事例 + 分解 | 実アプリの操作アニメーションの「型」 | ボトムシート、タブ切替、記録完了、数値カウントアップ |
| ui-ux-pro-max-skill | ルール / チェックリスト | 業種別デザインシステムと納品前チェック | 設計の初期方針、PR 前の品質ゲート |
| coss ui | 実装パターン | Base UI + Tailwind + CSS 変数トークン、コピペ所有型 | `src/components/ui/` の設計方針、トークンの持ち方 |
| HeroUI | 実装パターン | React Aria ベースの a11y、意味論トークン、compound API | Modal / Select / Tabs などの a11y 実装の答え合わせ |
| ThreeUI | 3D コンポーネント | Three.js / WebGL の表現とパラメータの参考値 | 運動タブのアバター、Daily Recap の演出（→ 08-3d.md） |

## 1. Inspora — https://www.inspora.design/

**何者か**
Web デザイン・ブランディング・プロダクトデザイン・モーション・イラスト・3D・印刷までを横断した、
毎時更新のキュレーションアーカイブ。1 投稿 = 1 プロジェクトで、カテゴリフィルタで絞り込める。
広告なしで「SNS のフィードを流し見る」代わりに使える静かなインプット源。

**得られるもの**
- 現在進行形のビジュアルトレンド（配色、余白の取り方、タイポの組み方）
- 1 プロジェクト単位でまとまっているので、単発の見た目ではなく「世界観の作り方」が見える

**使い方（このプロジェクトでの運用）**
- 新しいタブ・新しい大きめ画面を作る前に 10 分だけ眺めて、方向性を 1 つ言語化してから設計に入る
- 拾ったものは必ず「02-design-system.md のトークンで表現できるか」に変換してから実装する
- そのまま真似ない。健康記録アプリは「毎日 3 回以上開く道具」なので、装飾より一貫性を優先する

**注意**
インスピレーションサイトの事例はポートフォリオ／LP が多く、滞在時間が長い前提の演出が含まれる。
FitMealTracker の主要動線（食事記録）は 15 秒で終わるべきなので、演出はサブ画面に寄せる。

## 2. 60fps — https://60fps.design/

**何者か**
iOS / Android / Web の実プロダクトから集めた UI アニメーション事例ライブラリ。
「見た目のスタイル」ではなく **インタラクションの文脈** でフィルタできるのが特徴で、
Watch / 3D / AI / Assistant / Badge / Blur といった相互作用カテゴリと、
Health & Fitness / Food & Drink / Productivity などのアプリカテゴリの両軸で絞り込める。
`/storyboards` には 1 つのアニメーションをコマ単位で分解した解説があり、`/motion` はモーションのギャラリー。
動画は圧縮 GIF ではなくネイティブフレームレートで配信されるため、実際のタイミングが読み取れる。

**得られるもの**
- 同じ課題（例: 「モーダルを閉じる」）を各社がどう解いているかの比較
- オンボーディング、ボタン遷移、ローディング、ジェスチャの具体的な型
- タイミング感（何 ms でどう減速しているか）を目で測れる

**使い方（このプロジェクトでの運用）**
- **Health & Fitness / Food & Drink カテゴリを優先的に見る。**同ドメインの慣習に合わせるほうがユーザーは迷わない
- 拾った動きは 04-motion.md の duration / easing トークンに翻訳してから実装する
- 「かっこいいから」ではなく「どの認知コストを下げるか」を 1 行で書けるものだけ採用する

**注意**
事例の多くはネイティブアプリで、Web では同等の滑らかさが出ないものがある。
Web で再現するときは 04-motion.md の「transform / opacity のみ」制約を先に満たすこと。

## 3. ui-ux-pro-max-skill — https://github.com/nextlevelbuilder/ui-ux-pro-max-skill

**何者か**
プロダクトの業種・要件から「デザインシステム」を生成する AI スキル（MIT）。
79 の UI スタイル、192 の業種別カラーパレット、74 のフォントペアリング、192 の業種別推論ルール、
119 の UX ガイドライン、25 のチャート推奨、22 の技術スタック対応をデータとして持つ。
Claude Code / Cursor などにプラグインとして入れられる。

**このプロジェクトに効く中身**

*納品前チェックリスト（原文の要点）*
- 絵文字をアイコンに使わない（Heroicons / Lucide などの SVG を使う）
- クリック可能な要素に `cursor: pointer`
- インタラクションのタイミングはプラットフォームに合わせる
- ライトモードのテキストコントラストは最低 4.5:1
- キーボード操作時にフォーカス状態が見えること
- `prefers-reduced-motion` を尊重すること
- テキスト / チップ / バッジが折り返しても切れないこと
- レスポンシブ確認幅: 375px / 768px / 1024px / 1440px

*テキストとコンパクト UI の耐性*
- 見出しの折り返し制御は「あれば良い強化」であって保証ではない。狭い幅・ズーム・行間上書きでも読めること
- チップ / タグは折り返すか、操作可能な「+n」で省略する
- バッジの意味を色だけに依存させない

*アンチパターン*
- 業種に合わない派手なネオン、荒いアニメーション、文脈に合わないダークモード
- 「AI っぽい紫〜ピンクのグラデーション」を金融系に使う、など業種別の禁じ手

*Lifestyle カテゴリ（Habits / Recipes / Meditation / Diary / Mood）*
FitMealTracker はここに該当する。習慣化 UI・レシピ UI・記録 UI の推論ルールが参考になる。

**使い方（このプロジェクトでの運用）**
- チェックリストは 06-checklist.md に取り込み済み。PR 前に必ず通す
- 「MASTER + ページ別 override」というデザインシステムの持ち方は、
  このディレクトリ（02 = MASTER、画面固有の例外は各 PR の説明に書く）で代替する
- スキル本体を入れるかどうかは任意。入れなくてもチェックリストの価値は取れる

## 4. coss ui — https://coss.com/ui （リポジトリ: https://github.com/cosscom/coss）

**何者か**
Cal.com の公式デザインシステムとして公開されている React コンポーネント集（MIT）。
Radix からの移植ではなく **Base UI** の上にゼロから構築され、Tailwind CSS でスタイリングされている。
shadcn/ui と同じ「パッケージを入れるのではなくソースをコピーして自分のものにする」思想。

**中身の構造**
- **primitives** — Base UI の未スタイルのプリミティブ（アクセシビリティの難所を引き受ける層）
- **Particles** — 複数プリミティブを組み合わせた既製コンポーネント
- **Atoms** — SaaS でよくある API 呼び出しパターンまで含んだ層
- スタイルは Cal.com のデザイントークン体系（**CSS 変数 + Tailwind**）で実装されている
- 人間にも AI にも読みやすいことを設計目標に掲げている
- shadcn/ui CLI と v0 互換のレジストリを持つ

**このプロジェクトに効く学び**
1. **トークンは CSS 変数で持ち、Tailwind から参照する。**
   現状 `globals.css` に `--color-meal` などがあるのに、コンポーネント側は `bg-[#4CAF50]` と直書きが混在している（77 箇所）。
   coss の型に寄せて「CSS 変数 = 唯一の真実、Tailwind はその別名」に統一するのが正解。
2. **`src/components/ui/` を primitives 層として扱う。**
   現在ここには `Modal.tsx` しかない。Button / Field / Sheet / Chip / EmptyState をここに集約する。
3. **所有する。**外部 UI ライブラリを丸ごと入れず、必要なコンポーネントの実装だけを取り込んで自分で保守する。
   個人用 MVP + PWA という性格上、バンドルサイズと依存の少なさは実利がある。

## 5. HeroUI — https://heroui.com/ （旧 NextUI）

**何者か**
React Aria のアクセシビリティ実装と Tailwind CSS のユーティリティスタイルを組み合わせた React UI ライブラリ。
v3 は React Native も含めたゼロからの書き直しで、Tailwind CSS v4 ベース。

**中身の特徴**
- **アクセシビリティ最優先** — React Aria により、キーボード操作 / フォーカス管理 / スクリーンリーダー対応が WCAG 準拠
- **テーマ / トークン** — プラグインで既定テーマを上書きでき、意味論トークン（semantic tokens）ごと差し替え可能。
  v3 では CSS 変数・OKLCH カラー・BEM 修飾子を公開している
- **ダークモード** — HTML の theme 属性の変化を検知して自動的に切り替わる
- **ビルド時 CSS 生成** — ランタイム CSS-in-JS なし。Next.js / React 19 とそのまま組み合わせられる
- **compound API** — `Card.Header` / `Card.Content` / `Select.Item` のような合成 API。Provider ラッパー不要
- MCP サーバー、`llms.txt`、エージェント向けスキルなど AI 前提のツールも提供

**このプロジェクトに効く学び**
1. **意味論トークンで持つ。**`#4CAF50` ではなく `--accent-meal` / `--surface` / `--text-muted` のような
   「役割の名前」で持つと、後からダークモードやテーマ変更に耐えられる（02-design-system.md で採用）
2. **a11y は自作しない。**Modal のフォーカストラップ、Select のキーボード操作、Tabs の roving tabindex は
   自前実装だと必ず穴が出る。実装の答え合わせに HeroUI / React Aria のドキュメントを使う
3. **ランタイム CSS を増やさない。**現状 Tailwind + 一部インラインスタイル（Daily Recap 系）。
   ビルド時に解決される方向に寄せる

**採用するか？**
`@heroui/react` を導入すると PWA のバンドルが増える。現状の Tailwind 直書き構成のままで良い。
**参照するのは「思想と a11y の実装仕様」であって、依存として入れる必要はない。**
ただし Modal / Select / Tabs を作り直す場面が来たら、React Aria（`react-aria-components`）だけを
ピンポイントで入れる選択肢は検討に値する。

## 6. ThreeUI — https://threeui.com/browse （リポジトリ: https://github.com/MengTo/threeui）

**何者か**
Three.js / WebGL 製のインタラクティブ UI コンポーネントとシェーダーのカタログ。
`/browse` がグリッド + 検索 + テーマ切替のブラウズ画面で、各コンポーネントのページに
**ライブプレビュー・バリアント選択・コントロール（パラメータ調整）・ソースコードタブ**がある。
オープンソースの **ThreeUI Community**（ログイン不要）は 50 の親コンポーネント / 111 ルート / 164 のブラウズ結果を含み、
アプリコードと Community コンポーネントは MIT（同梱フォントは SIL OFL 1.1、Three.js は元の MIT）。
`npm install @designcodeio/threeui` でパッケージとしても入る。React + Three.js + WebGL シェーダー、Vite + TypeScript 構成。

**得られるもの**
- プロシージャルな 3D ヒーロー / アイコン / モーションの実装（**テクスチャ資産を配らずに 3D を出す**手法）
- 「テーマ / ライティング / モーション / レイアウト」という調整軸の切り方
- 減衰・回転速度・カメラ距離などの **数値の当たり**。一から詰めなくてよくなる
- ソースをコピーして所有する前提（coss ui と同じ思想）。プロンプトも同梱されている

**FitMealTracker での位置づけ**
このプロジェクトは既に `three` + `@react-three/fiber` + `@react-three/drei` を使っていて、
運動タブの種目デモアバターは **装飾ではなく機能**（フォームを見せる）として動いている。
そのため ThreeUI は「インスピレーション」ではなく **実装の参照元**として扱い、
運用規約は独立したファイルに切り出した。

→ **[08-3d.md](./08-3d.md)** を参照（使ってよい場所、アセット予算、`frameloop` と停止条件、
a11y、`prefers-reduced-motion`、WebGL フォールバック）

**注意**

- **依存として `@designcodeio/threeui` は入れない。**PWA の初回ダウンロード量が体験に直結する。
  必要な表現の実装だけを読んで自前で書く
- カタログの作例はデスクトップの LP を想定したものが多く、ライトやポストプロセスを気前よく使っている。
  そのまま持ってくるとモバイルでフレームを落とす。08-3d.md §3 の予算に当ててから入れる
- 同梱プロンプトをそのままエージェントに渡すと規約を無視した実装が出る。制約を追記してから使う
